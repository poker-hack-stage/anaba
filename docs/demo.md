## 2. 発表前のチェックリスト

役割を先に決める: **操作する人**・**話す人**・**見張り役**（口コミ・投稿の見張り。発表中は操作しない）・**Supabase と Vercel の持ち主**（hayato-psg）。

本番の Supabase と Vercel のダッシュボードを触れるのは持ち主だけ（ほかのメンバーは招待しない。README の「外部サービス」）。SQL Editor で非表示にする・止める・Restore する・環境変数を変える操作は、すべて持ち主が行う。**見張り役は持ち主が兼ねる**のがよい。兼ねられないときは、見張り役は本番の画面で見張り、見つけたら持ち主に伝える。

### デモモードに切り替える

**アプリの画面には、デモモードに切り替える操作はない。** 次のどれかで自動で切り替わる（コードは `lib/planner/create-plan.ts`・`lib/ai/gemini.ts`・`app/api/plan/route.ts`・`components/planner/planner-form.tsx`）。

| いつ                                                                                                                             | どこで作るか                                   | 画面の表示                                                                                              |
| -------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `GEMINI_API_KEY` が空・Gemini が45秒で返らない・レート制限（429）・安全フィルター・通信エラー・出力の形が崩れた・使える候補が0件 | サーバー（`/api/plan`）                        | 「デモモードで作成しました。」                                                                          |
| レート制限の回数を数えられない（`RATE_LIMIT_SALT` が空・DB のエラー・3秒で返らない）                                             | サーバー（Gemini を呼ばない）                  | 「デモモードで作成しました。」                                                                          |
| 同じ IP から10分に100回を超えた（`/api/plan` が 429）                                                                            | ブラウザ                                       | 「短い時間に何度も作ったため、デモモードで作成しました。しばらくしてからつくり直すと、AI で作れます。」 |
| `/api/plan` がエラー・55秒で返らない・つながらない                                                                               | ブラウザ（読み込み済みの地域とスポットで作る） | 「デモモードで作成しました。」                                                                          |

**手で切り替える手順**（Gemini が遅い・不安定なとき。操作できるのは Vercel の持ち主だけ）:

1. Vercel のプロジェクト `anaba` → Settings → Environment Variables で、Production の `GEMINI_API_KEY` を消す（値は控えておく）
2. Deployments の一番上の `…` → Redeploy。環境変数は Redeploy するまで反映されない
3. 本番で旅プランを1回つくり、「デモモードで作成しました。」が出ることを確かめる
4. 戻すときは、`GEMINI_API_KEY` を入れ直して、もう一度 Redeploy する

- Redeploy は数分かかる。発表の直前・最中には切り替えない（その間は前のデプロイが動いている。切り替えが間に合わなくても、Gemini が失敗すればその場でデモモードになる）
- `RATE_LIMIT_SALT` は消さない。旅プランはデモモードになるが、口コミ・投稿が 503 で止まる
- デモモードの候補は、興味に合うスポットを穴場度の高い順に選ぶ。同じ条件なら毎回同じ候補になる。希望欄は一部のキーワードだけ反映する

## 5. 想定質問と答え

| 質問                                  | 答え                                                                                                                                                                                                     |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 穴場度はどう決めているのか            | データを作る人が、3つの観点（観光客の少なさ・知名度の低さ・地元の人のおすすめ度）で1〜5を手で付けている（docs/spot-scores.md）。口コミの数からの自動計算はしていない                                     |
| AI が存在しない場所をでっち上げないか | Gemini には、候補にできる地域のスポットのデータだけを渡し、返ってきた経路のスポットが実在するか・その日の地域にあるかをサーバーで確かめる。決まりに合わない候補は捨て、1件も残らなければデモモードにする |
| AI が使えないときはどうなるのか       | デモモードで、興味に合うスポットを穴場度の高い順に選んで候補を作る。キーがない・45秒で返らない・無料枠を超えた、のどれでも止まらない                                                                     |
| なぜ Gemini なのか                    | 無料枠（1分15回・1日500回）で発表と開発をまかなえるため。モデルは環境変数で切り替えられる                                                                                                                |
| ログインなしで荒らされないか          | 同じ IP から口コミは10分に3件・投稿は1時間に2件まで、全体でも上限がある。NG ワードで弾き、すり抜けたものは管理者が SQL で非表示にする。いざとなれば受け付けだけを止められる（docs/moderation.md）        |
| 写真の権利は大丈夫か                  | Wikimedia Commons のうち CC BY・CC BY-SA・CC0・パブリックドメインのものだけを使い、そのスポットが写っていると確かめた。撮影者とライセンスは「写真の出典」ページに出している（docs/image-credits.md）     |
| 地域の境界のデータはどこから          | OpenStreetMap の市町村の境界（© OpenStreetMap contributors、ODbL）。地図の帰属表示に出している（docs/boundaries.md）                                                                                     |
| スポットの情報は正しいのか            | 公式サイトや自治体のページで確かめ、出典を docs/spot-sources.md に残している。休みや時期は変わるので、行く前に公式の情報を見てもらう                                                                     |
| 参考 PoC とどこが違うのか             | 地図と巡回で「探す」を作り直し、全国12市町村に広げ、写真の権利を確かめ、旅プランを候補3件の比較と経路の組み直しにした（改良点の表）                                                                      |
| 宿や移動時間は入るのか                | 宿は含まない。移動は手段ごとの目安で所要時間に入れているが、実際の経路検索はしていない                                                                                                                   |
| お金はかかるのか・続けられるのか      | Vercel（Hobby）・Supabase（Free）・Gemini（無料枠）・OpenFreeMap（無料）で動いている。Supabase の Free は1週間アクセスがないと一時停止するので、続けるなら有料プランか定期的なアクセスが要る             |
| 地域を増やすには                      | 地域とスポットのデータ（`supabase/seed.sql`）と境界（`scripts/boundaries/build.mjs`）を足す。地域とスポットは DB から読んでいるので、データを足せば画面と旅プランに出る                                  |
