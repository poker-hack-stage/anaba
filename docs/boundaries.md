# 地域の境界データ（areas.boundary）

`supabase/seed.sql` の末尾にある `update public.areas set boundary = …` の12行は、`scripts/boundaries/build.mjs` が作る（#10）。手で編集しない。

| 項目       | 内容                                                                                                                             |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------- |

| 提供       | 国土交通省（国土数値情報ダウンロードサイト <https://nlftp.mlit.go.jp/ksj/gml/datalist/KsjTmplt-N03-2025.html>）                  |

| 表示       | 地図や画面に出すときは「出典：国土数値情報（行政区域データ）（国土交通省）を加工して作成」をクレジットに書く（地図の部品は #14） |

### 測量法に基づく承認（要判断）

配布ページには、ライセンスの表記とは別に、次の記載がある（原文のまま）。

| 項目           | 配布ページの記載                                                              |
| -------------- | ----------------------------------------------------------------------------- |
| 原典           | 国土地理院「数値地図（国土基本情報）」の行政区画データから整備                |
| 承認番号       | 「測量法に基づく国土地理院長承認（複製）R 6JHf 503」                          |
| 複製の条件     | 「本製品を複製する場合には、国土地理院の長の承認を得なければなりません。」    |
| 二次利用の注記 | 「※本データを二次利用する場合には、国土地理院に申請等必要な場合があります。」 |

このリポジトリは public なので、マージすると加工した境界データを公開することになる。このアプリの使い方（間引いた境界を seed に入れ、Web 地図に重ねて見せる）で国土地理院への承認・申請が要るかは、**人が判断する必要がある**（まだ判断していない）。判断の材料は国土地理院の「測量成果の複製・使用」の案内（<https://www.gsi.go.jp/LAW/2930-index.html>）。

一部の市区町村では境界が未確定で、原典で暫定の線が引かれている（配布ページの注記）。

## 形

- `boundary` は GeoJSON の geometry（`{"type": "Polygon" | "MultiPolygon", "coordinates": …}`）。Feature ではない（名前などは `areas` の列にある）
- 座標は `[経度, 緯度]`。測地系は JGD2011（Web 地図の WGS84 との差は1m 未満なので、そのまま Leaflet に渡してよい）
- 今の12地域はどれも `Polygon`（飛び地なし）だが、読む側は `MultiPolygon` にも対応しておく

## 間引きの強さとサイズ

北アルプス山麓の5地域は細かめ、ほかの地域は粗めにしている（Issue #10 の目安）。

| 区分                | 頂点を残す割合 | 座標の桁         | 1地域の上限 |
| ------------------- | -------------- | ---------------- | ----------- |
| 北アルプス山麓（5） | 10%            | 小数5桁（約1m）  | 25KB        |
| ほかの地域（7）     | 6%             | 小数4桁（約10m） | 10KB        |
| 合計（12）          |                |                  | 200KB       |

## 作り直す手順

地域を足したり、N03 の新しい年度に替えたりするとき。

1. `scripts/boundaries/build.mjs` の `AREAS` に、`seed.sql` と同じ id・県名・市町村名・行政区域コード（N03_007）を足す。年度を替えるなら `N03_VERSION` と `N03_DATE` を直す
2. 実行する（初回は都道府県ごとの zip を配布元からダウンロードする。北海道は約57MB）

   ```bash
   node scripts/boundaries/build.mjs --check   # サイズの確認だけ
   node scripts/boundaries/build.mjs           # seed.sql を書き換える
   ```

3. サイズの上限を超えたら、`GROUPS` の `keep` を下げる
4. `npm run db:reset` で投入できることを確かめ、地図に重ねてずれがないかを見る

必要なもの: Node.js 22、`unzip` コマンド、ネットワーク（mapshaper は `npx` で取得する。package.json には入れていない）。ダウンロードした zip は OS の一時ディレクトリの `anaba-n03/` に置く（`N03_CACHE_DIR` で変えられる）。リポジトリには入れない。
